## 2. “全部功能可达”的三层保障

1. **手机版 UI（`/#/m`）**：首页 / 新闻 / 互动 / 活动 / 教程 / 加入 / 任务 / 待办 / 审核台 / 通知 / 我的
   —— 覆盖绝大多数阅读与轻量操作；
2. **降级入口（区块 8，网站 PR #266）**：做不了移动版式的页面挂在「我的」里，**桌面版式但可达可操作** ——
   常用组有私信、个人资料、登录设备、意见反馈、社员查询；「更多」组有考试看板（`/exam`）、
   课表（`/schedule`）、全景图（`/panorama`）、关于我们（`/about`）；管理员另有「进入后台管理」；
3. **壳版本闸门（区块 8，网站 PR #266）**：网站从 UA 解析 `versionCode`，低于
   `MIN_SHELL_VERSION_CODE`（当前 2 = v0.2.0）时全屏提示更新并给 APK 直链 ——
   老壳缺原生能力时（例如网页内相机授权），用户至少知道是版本问题，而不是"点了没反应"。

> 壳（区块 2）与网站（区块 8）是两件事：本表里 "2 + 8" 的行，壳那一半早已完成
> （能选文件/拍照/下载），网站那一半的**入口**由区块 8 补齐（网站 PR #266）；标 🟡 的行只差真机回归。

| SurveyJS 问卷编辑 | 手机屏小、拖拽困难 | 真机做一次"新建问卷 + 作答" |
| tus 大文件上传 | 切后台/息屏可能中断 | 传一张 8 MB 原图，中途锁屏 |
| 相机拍出的临时 URI | 部分国产 ROM 不传 `EXTRA_OUTPUT` / 拒绝 URI 授权 | 真机点选择器里的"相机"，拍一张并上传成功 |
| 分享图片文件本体 | 接收方（微信/QQ）对 `content://` 流的兼容性 | 长按图片 → 分享图片 → 发到微信文件传输助手并打开 |
| Android 8/9 的下载落盘 | 首次会弹存储权限；拒了则落 App 目录 | 拒绝权限后重试，能从通知栏打开文件 |
| Live2D | 60 MB 素材在 3 M 带宽下很慢 | 网站侧按视口宽度不挂载 + **壳侧兜底拦截**（区块 6，`blockLive2dAssets`）；实测 App UA 零 live2d 请求 |
| 弱命令 WebView | 部分国产机 WebView 版本旧（<80）不支持可选链 | 检测 WebView 版本，低于阈值提示升级"Android System WebView" |
| 更新包自升级（L2） | 部分 ROM 对「安装未知应用」限制更严（需逐次确认）；下载中断需能续传 | 真机走一遍：提示 → 下载 → 中途杀进程 → 重进续传 → 安装 → 登录态保留 |
| 更新签名比对 | 若用 debug 包验收 release 包会"签名不一致"（这是正确行为） | 验收时用同一签名的包；换签名只允许"卸载重装" |
| 大资源拦截误伤 | 拦截白名单写错会拦掉正常资源（表现为页面缺图/脚本 404） | 白名单唯一真源在 `AppConfig.BLOCKED_ASSET_PREFIXES`（只列"不必要"的前缀）；预检钉住"主文档不拦 + 空体 200"；真机看页面是否正常 |
| 探测降频 | 退避过头会让状态栏配色跟不上站内切主题 | 最多退避到 15 s / 30 s，且在"有变化/回前台/导航"时立刻回快档；滚动与手势的主信息源是 `onScrollChanged`（不依赖探测） |

## 5. 维护规则

- 网站新增路由 → 同步在本表加一行（网站仓库的 PR 里一起改，或由 App 侧跟进）；
- 每行状态从 ⏳/🟡 变 ✅ 时，必须注明验证人 + 验证日期 + 机型；
- 本表是验收清单，不允许"默认已支持"；
- **跨仓库事实**（2026-10-11 核对）：网站里所有 `<input type="file">` 用的是 `accept="image/*"`、
  `accept="image/*,video/*"`、`accept=".pdf,.docx"` 这类写法，**没有任何一个写了 `capture` 属性**。
  所以壳不能只看 `isCaptureEnabled()`，否则"拍照"入口永远不出现（已在壳的单测里钉死）。
