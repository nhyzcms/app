# 排查：进 App 后空白（2026-10-12 第二起 · 第二轮）

> 承接 `FIX-20261012-BLANK-SCREEN.md`。首轮修复（PR #11）解决了"骨架浮层永不揭开"，
> 但真机上**画面依旧空白**，且**等了 15 秒也没有出现诊断浮层**。

## 1. 决定性证据：App 从未向站点发出任何请求

查服务器 nginx `access.log`（`ssh nhyz`）：

- 全日志中带 App 标记（`NhyzClubApp`）的请求**只有 1 条**，而且是排查时自己用 curl 发的；
- 更没有 `/app-update/manifest.json`（App 每次启动都会检查更新，请求一定会带同一个 UA 标记）。

⇒ **不是浮层盖住，也不是站点问题**：壳里的 WebView 连请求都没发出去。
再叠加两个现象，指向同一件事：

1. 首轮修复里的"探测式揭开"没生效；
2. 基于 JS 回调的 15 秒诊断也没出现。

两条路都依赖 `evaluateJavascript` 的回调 —— 如果 WebView 里**根本没有文档**
（请求没发出去 / 一直挂着），回调永远不回来，于是既不会揭开、也不会诊断。

最可能的原因是**这台手机没有给这个 App 联网权限**（HarmonyOS/EMUI 的"应用联网"管控，
侧载 App 尤其常见），其次是网络层被拦（挂起而非立刻报错，所以连 `onReceivedError` 也没有）。

## 2. 本轮改动（`shell/feel/FeelHost.kt`）

| # | 改动 | 为什么 |
| --- | --- | --- |
| ① | **硬看门狗（12 s，纯计时）**：不依赖任何 JS 回调，到点无条件揭开骨架并列诊断 | 上一轮的诊断挂在 `evaluateJavascript` 回调里，回调不来就永远不触发（本次就是这个坑） |
| ② | **壳侧 HTTP 探测**：后台线程对站点发一次 `HEAD`，把"HTTP 状态码"或"异常类名 + 消息"写进诊断 | 一句话区分两种故障：**App 没网**（探测同样失败）vs **只有 WebView 没加载**（探测能拿到 200） |
| ③ | **页面脚本探测状态**写进诊断（`PageStateProbe` 是否有结果） | 有结果 = WebView 里 JS 正常；无结果 = JS 根本没跑 |
| ④ | **onPageFinished 之后 5 s 复核 DOM**：加载完了但 DOM 是空的（脚本没跑）也要列诊断 | 覆盖"页面finished但什么都没渲染"这一支，用户不必对着纯空白 |
| ⑤ | 关键事件落盘 `filesDir/diag/last-run.txt`（上限 64 KB） | 浮层只解决"当下看得见"；落盘后即使 App 被系统杀掉也能取出轨迹 |
| ⑥ | 内容后来出来了就撤掉诊断浮层 | 诊断只是"当时没画面"的临时说明 |

诊断浮层现在包含：地址、网页脚本开关、WebView 内核版本、`#root/body/script/bundle` 计数、
**页面脚本探测是否有结果**、**壳侧网络探测结果**（最多信息量的一条）。

## 3. 验证

- 本地：`scripts/preflight.sh` ✅、括号/字符串/注释配平 ✅、
  `/workspace/klocaltest.sh` 真实 Kotlin 编译 + JVM 单测 **127 tests OK**。
- CI：preflight + `:app:testDebugUnitTest` + `:app:assembleDebug`。
- 真机（验收点）：
  - 若 App 有网：12 秒内应看到网页内容（骨架被揭开）；
  - 若 App 没网：12 秒后底部出现诊断浮层，**其中"本机网络探测"会是异常（如 `ConnectException`/`SocketTimeoutException`）**
    —— 那就说明要去系统里给「南汇一中传媒社」打开联网权限（设置 → 移动网络/流量管理 → 应用联网），
    而不是继续改代码。

## 4. 教训

1. **不要把"关键兜底"挂在异步回调上**：回调可能永远不来（WebView 没有文档、JS 被禁、渲染进程异常）。
   兜底必须是纯计时的（本轮 ①）。
2. **先确认"请求有没有发出去"**：服务器日志是最便宜、最客观的证据；比在客户端猜浮层、猜颜色快得多。
3. 客户端自诊断要有**能区分网络层与渲染层**的一条信息（本轮 ②），否则拿到"空白"还是无从下手。
