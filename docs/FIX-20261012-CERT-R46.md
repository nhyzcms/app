# 修复：App 空白屏的真正原因 —— 证书链的根不在设备信任库里

> 承接 `FIX-20261012-BLANK-SCREEN.md`（骨架浮层）与 `FIX-20261012-BLANK-SCREEN-2.md`（硬看门狗 + 诊断）。
> 第三轮的诊断浮层终于把答案交出来了。

## 1. 决定性证据（来自 App 自己的诊断浮层）

```
地址：(空)
网页脚本：已开启
WebView 版本：114.0.5.302
内容探测：#root 子节点 -1，body 长度 0，script 标签 0，站点打包全局 无
页面脚本探测：有结果（JS 正常）
本机网络探测：SSLHandshakeException:
    java.security.cert.CertPathValidatorException: Trust anchor for certification path not found.
```

- `地址：(空)` + `body 长度 0` + `script 标签 0` ⇒ **WebView 里连文档都没有**（导航在握手阶段就死了，
  没提交任何页面）；这也解释了为什么连 `onReceivedError` 都没触发。
- `页面脚本探测：有结果` ⇒ 壳与 WebView 都正常，JS 能跑。
- `本机网络探测：SSLHandshakeException … Trust anchor for certification path not found`
  ⇒ **设备的系统信任库验证不了站点的证书链**（壳自己的 `HttpURLConnection` 也失败了，
  所以不是 WebView 特有的问题）。

## 2. 根因

服务器（`openssl s_client` 实测）发出的链是**完整的两张**：

| # | 主题 | 签发者 | 有效期 |
| --- | --- | --- | --- |
| 1 | `CN = 8.153.145.175` | `ZeroSSL RSA DV SSL CA 2` | 2026-08-28 → 2026-11-26 |
| 2 | `ZeroSSL RSA DV SSL CA 2` | **`Sectigo Public Server Authentication Root R46`** | 2025-09-24 → 2035-09-23 |

链不缺中间证书，缺的是**根**：`Sectigo Public Server Authentication Root R46`
（2021-03-22 签发，**2046-03-21 到期**）**不在老设备的信任库里**。
实测设备：HUAWEI P40 Pro+ / HarmonyOS 4.2 = Android 12 内核。

- 用 Ubuntu 的 CA 库验证：`openssl verify -CAfile <R46> -untrusted <中间> <叶子>` → **OK**；
- 同一台设备的 App（系统信任库）→ **Trust anchor not found**。

⇒ 这不是壳的 bug，也不是站点"挂了"，而是**证书链的根与老设备的信任库不匹配**。
（同时也要注意：这台手机的**浏览器**大概也打不开该站点，只是浏览器会给出"证书不受信任"的提示，
比 App 的白屏更容易看懂。）

## 3. 修复（App 侧，本 PR）

把该根证书作为**额外信任锚**打进 App，让 WebView 的证书校验能走通：

- 新增 `app/src/main/res/raw/sectigo_r46.pem`（Sectigo R46 根，公钥证书，2046-03-21 到期）；
- `res/xml/network_security_config.xml`：
  - `base-config` 的 `trust-anchors` 里加 `<certificates src="@raw/sectigo_r46" />`；
  - ⚠️ **`debug-overrides` 也要加一遍** —— 它会**替换**（不是追加）base-config 的信任锚，
    而用户装的正是 debug 包；漏了这一处修了也没用。

安全影响：只**增加**一个公开根证书的信任，不移除系统根、不做证书固定（站点 90 天换证，
固定必在换证日全量失联，见 ADR-A03）。站点换 CA 时需要同步维护这个文件。

## 4. 站点侧（需要管理员决策，App 改不了）

同一台设备的浏览器同样受这个根的影响。两个选择：

1. **换到有"老根"链的证书**：重新签一张链到 `USERTrust RSA Certification Authority`
   或其它老根的证书（若 CA 提供 alternate chain）；
2. **上域名 + Let's Encrypt**（推荐）：ISRG Root X1 覆盖 Android 7.1.1 以上所有设备，
   顺带解决 App Links 官方校验（当前用 IP 无法做 `assetlinks.json` 校验）。

在此之前，App 侧用本 PR 的信任锚兜住，保证 App 可用。

## 5. 教训

1. **"打不开"的第一条排查不是猜 UI，而是问网络层**：这一轮的 `本机网络探测`（壳自己发一次请求）
   一句话就把范围从"浮层/渲染"缩到了"TLS 信任"。
2. **证书链的根也要考虑新旧**：`Sectigo … Root R46`、`ISRG Root X2` 这类 2021 年后的根
   在老设备上并不可靠；面向学生群体的站点要以"最老的设备"为准。
3. **`debug-overrides` 是替换语义**：给 debug 包加信任锚时必须两处都写。
