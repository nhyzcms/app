# 原生扫码核验（工牌二维码 / Code128）

> 目标：活动现场不用网页、不用手输编号 —— 在 App 里扫一下工牌，直接出社员的公开信息卡。
> 相关代码：`app/src/main/java/com/nhyzcms/clubapp/shell/scan/`（3 个文件，约 150 行）。

---

## 1. 入口与观感

- 入口是**右下角一颗 44 dp 的品牌色圆钮**（白色取景框图标），常驻在「返回顶部」按钮上方；
  页面首屏画完才出现，错误面板盖着时自动隐藏（判定见 `ScanEntryPolicy`，有单测）。
- 清单开关 `showScanEntry`（默认 `true`）可远程撤掉这颗按钮，不用发版（见 [APP-MANIFEST.md](APP-MANIFEST.md) §3）。
- 取景页：竖屏、黑底，顶部「扫码核验身份」标题 + 关闭钮 + 手电筒钮，底部是 ZXing 的取景框与提示语。
- 点下去先要相机权限；被拒时弹中文说明并可直达系统设置（不反复弹系统框）。

## 2. 一次扫码发生了什么

```
点圆钮
  └─ 没有相机硬件 → toast「这台设备没有可用的摄像头」
  └─ 没有相机权限 → 申请；拒了 → 中文引导（去设置 / 取消）
  └─ ScanActivity（竖屏取景，只认 QR_CODE + CODE_128）
        └─ 识别到文本 → RESULT_OK + SCAN_RESULT
              └─ ScanRouter.targetUrl()   ← 纯逻辑，决定「能不能接管、落到哪」
                    ├─ 本站链接（二维码）→ 原样打开（`/#/v/<码>?s=<签名>`）
                    ├─ 8 / 12 位数字（条形码）→ `/#/v?q=<数字>`
                    └─ 其它 → toast「扫到的内容不是本站工牌」
```

落到网页后，**查询与展示全部复用网站现有实现**（`MemberLookupPage` / `MemberVerifyPage` + `MemberResultCard`），
壳里不复制一份业务判断，也不自己画结果卡 —— 这是本仓库「界面与业务 100% 在网页」的分层约定。

## 3. 为什么这么设计（三个被否掉的替代方案）

| 方案 | 为什么不用 |
|---|---|
| 在 WebView 里调 `getUserMedia` + 网页 ZXing | 国产 ROM 的 WebView 摄像头极不稳定；网页版还要按需下载 ~950 KB 的 ZXing chunk，服务器只有 3 M 带宽 |
| 扫完用 `evaluateJavascript` 把文本送进网页 | 违反安全边界：壳内执行 JS **只允许常量脚本**（[SECURITY.md](SECURITY.md) §4.1）。扫码内容是外部输入，任何人可以打一张二维码 |
| 直接用库自带的 `CaptureActivity` | 它的清单写死 `sensorLandscape` 与 `clearTaskOnLaunch`：凑近工牌时界面先横过来再转回去；且没法加自己的标题/手电筒 |

代价：`zxing-android-embedded` ≈150 KB + `zxing core` ≈600 KB，**APK 约 +0.7 MB**。
换来的是一进页面就出取景框（不等网络）、每帧只解两种码（低端机跟得上）。

## 4. 与网站仓库的契约

| 扫到的内容 | 落点 | 谁判断 | 额度 |
|---|---|---|---|
| `https://8.153.145.175/#/v/<8 位码>?s=<16 位签名>` | 校验页 | 网站（`/member/check/`） | **不消耗** |
| 12 位数字（6 位唯一键 + 6 位十进制短签名） | `/#/v?q=<12 位>` | 网站（`MemberLookupPage` 自动查一次） | **不消耗**（签名即证明） |
| 旧的裸 8 位识别码 | `/#/v?q=<8 位>` | 网站 | 按查询者身份分档扣额度 |
| 非本站链接 / 其它文本 | —— | 壳（`ScanRouter`，直接拒绝） | —— |

网站侧的 `?q=` 深链接在网站仓库 PR「feat(社员查询): /#/v 支持 ?q= 深链接」里，`q` 只在值变化时查一次
（避免 WebView 重挂载白扣额度）。**网站侧未合并前**，条形码这条路会落到「未找到」，二维码那条不受影响。

`ScanRouter` 的安全边界（都有单测）：

- 只接管 host 等于 `AppConfig.SITE_HOST` 的链接，`http://` 一律改写成 `https://`；
- 裸数字只认 8 / 12 位，先去掉空格 / 制表符 / 短横线（扫码枪常带这些）；
- 文本超过 256 字符直接拒绝，不往地址栏里塞垃圾。

## 5. 一个容易踩的坑：hash 路由不回调 `onPageFinished`

站内地址都是 `https://host/#/...`。从 `/#/m` 跳到 `/#/v?q=...` **只有片段变了**，
WebView 不会触发 `onPageFinished` —— 进度条会一直转，扫码按钮也一直藏着。
所以 `openScannedText()` 在 `load()` 之后排了一次 600 ms 的收尾（`settleSameDocument`）：
真发起网络时 `onPageFinished` 会先到，这个 Runnable 就自然空转一次。

## 6. 真机验收清单（8 条）

> 状态：🟡 代码就绪，待管理员真机验收（按仓库惯例，验证后在 [FEATURE-MATRIX.md](FEATURE-MATRIX.md) 第 34 行改 ✅ 并注明机型/日期）。

1. 首页右下角能看到品牌色扫码圆钮，**向上滚动出现「返回顶部」时两颗按钮不重叠、不挡内容**；
2. 断网 / 服务器挂掉（错误面板）时圆钮消失；
3. 首次点扫码会弹相机权限；**拒绝**后出现中文说明，点「去设置」能直达本应用权限页；
4. 扫**工牌二维码** → 落到 `/#/v/<码>?s=...`，出姓名 / 届数 / 在册状态；
5. 扫**条形码**（12 位）→ 落到 `/#/v?q=...` 并自动查一次，额度提示没有减少；
6. 扫同一张工牌**连续两次**不重复扣额度（`q` 未变化不重查）；
7. 扫一张**别人的二维码**（例如购物链接）→ toast「扫到的内容不是本站工牌」，不跳转；
8. 室内暗光下点手电筒能亮；关掉后再开取景页，手电筒是关的（按钮取景不撒谎）。

## 7. 发版注意

- 这是**原生能力变更**（新依赖 + 新 Activity），属于 L2 **冷更新**：网站发版不会带上它，必须发新 APK；
- 清单开关 `showScanEntry` 可以先在服务器 `app-manifest.json` 里关掉，等于把入口藏起来（灰度兜底）；
- 目录 `shell/scan/` 的改动必须同时跑 `bash scripts/preflight-scan.sh`（会被 `preflight-feel.sh` 连带执行，CI 已覆盖）。
